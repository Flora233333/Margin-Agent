## 三、一道题的数据流（对应上面的文件）

```text
run_episode.py
  │  组装：Corpus + HybridRetriever(BM25, Alias, Dense) + OpenAICompatibleClient
  ▼
loop.run_episode(task, llm, registry)
  │  messages = [system 提示词, 题目]                       ← prompt.py
  │  循环：
  │    response = llm.chat(messages, 十个工具说明)          ← llm/client.py
  │    检查：每轮必须恰好调用 1 个工具
  │    result = registry.execute(工具名, 参数JSON)           ← tools/base.py
  │               ├ args.py 校验参数，不合格 → bad_args 返回给模型
  │               ├ 调用具体工具 search / reading / actions
  │               └ 包装成 {"ok": true, "data": …} 或 {"ok": false, "error": …, "hint": …}
  │    write_note 成功 → 丢掉历史，只留 [system, 题目, 最新笔记]（压缩）
  │    否则 → 把 result 作为 tool 消息追加到 messages
  │    检查停止条件（打转、重复报错、轮数用完……）
  │    finalize / escalate 成功 → 结束
  ▼
Trace：每一轮的思考、工具、参数、结果、耗时、token
```

## 五、review 时请重点看的地方

1. **`loop.py` 的停止条件**：7 种停止原因的阈值（打转 3 次、同错 3 次、格式错 6 次、30 轮）都照搬 RC6-C，
   是自训模型训练时的规则，改动会让评测结果不可比。
2. **`tools/base.py` 的错误处理**：工具内部的 `KeyError / ValueError / ArithmeticError` 统一转成
   `invalid_request` 返回给模型——这是有意的“错误恢复”。其他异常（如网络错误、TypeError）会直接抛出。
   代价：程序 bug 如果恰好也抛 KeyError，会被当成参数问题交给模型，日志里不显眼。
3. **`dense.py` 的精确检索**：不建 HNSW 索引的理由见 D15（数据量小、近似检索会漏结果）。
4. **两份“模型接口”文件**：`system_rc6c.txt`、`tool_schemas.json` 原样来自 RC6-C，不在本项目里改。

### 一道题在后端的数据流

```text
POST /runs ─► api.create_run ─► runs.create_run
                                  一个事务：runs + attempts(pending) + outbox(pending) + events
dispatcher.dispatch_once ─► celery send_task ─► redis
worker.execute_attempt ─► worker.execute
  ├─ lease.claim            pending -> running，epoch+1（重复消息在这里被挡掉）
  ├─ lease.LeaseKeeper      每 15 秒 lease.renew
  ├─ run_episode(on_step=lease.commit_step)
  │     每一步一个事务：校验 epoch + 续租 + steps + events
  └─ lease.finish / lease.fail
dispatcher 每 15 秒 lease.expire_leases：过期的 running -> failed，epoch+1
GET /runs/{id}/events ─► runs.events_after（先读状态、后读事件）
```

### review 时请重点看

1. **`runs.add_event` 为什么不用自增 id 当序号**（注释里有反例）。
2. **`runs.events_after` 的查询顺序**：先状态后事件，反过来会漏掉“结束”事件。
3. **`lease._fence`**：所有写入都带 `lease_epoch = 我的 epoch` 条件，更新 0 行就抛 `LeaseLost` 回滚。
4. **`worker.execute` 的异常处理**：`LeaseLost` 什么都不写直接退出；其他异常判失败，
   错误只记类型 / 状态码（httpx 报错里带网关地址）。
5. **`dispatcher.dispatch_once` 的“至少一次”**：发了消息但标记 sent 没提交，会重发；重复由 `claim` 挡住。
