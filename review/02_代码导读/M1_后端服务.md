## 三、一道题在后端的数据流

```text
POST /runs ─► api.create_run ─► runs.create_run
                                  一个事务：runs + attempts(pending) + outbox(pending) + events
dispatcher.dispatch_once ─► celery send_task ─► redis
worker.execute_attempt ─► worker.execute
  ├─ lease.claim            pending -> running，epoch+1（重复消息在这里被挡掉）
  ├─ lease.LeaseKeeper      每 15 秒 lease.renew
  ├─ run_episode(on_step=lease.commit_step)
  │     每一步一个事务：校验 epoch + 续租 + steps + events
  └─ lease.finish / lease.fail
dispatcher 每 15 秒 lease.expire_leases：过期的 running -> failed，epoch+1
GET /runs/{id}/events ─► runs.events_after（先读状态、后读事件）
```

## 五、review 时请重点看的地方

1. **`runs.add_event` 为什么不用自增 id 当序号**（注释里有反例）。
2. **`runs.events_after` 的查询顺序**：先状态后事件，反过来会漏掉“结束”事件。
3. **`lease._fence`**：所有写入都带 `lease_epoch = 我的 epoch` 条件，更新 0 行就抛 `LeaseLost` 回滚。
4. **`worker.execute` 的异常处理**：`LeaseLost` 什么都不写直接退出；其他异常判失败，
   错误只记类型 / 状态码（httpx 报错里带网关地址）。
5. **`dispatcher.dispatch_once` 的“至少一次”**：发了消息但标记 sent 没提交，会重发；重复由 `claim` 挡住。
